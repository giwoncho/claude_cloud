🆚 Shen vs G11BM — 정확히 무엇이 같고 무엇이 다른가

🧓 Shen 2024 (원본)

  • 축: 시간(나이) 25→75세
  • 샘플 단위: 사람 108명
  • 측정: 4 sample × 10 omics multi-modal
  • 결과: 봉우리 @44, @60 (전신 노화 transition)
  • 코드: R, tidymass+DEswan

🐭 본 prototype (G11BM 어댑테이션)

  • 축: SenePy sp_best 점수
  • 샘플 단위: 세포 (→ score-bin pseudobulk로 묶음)
  • 측정: scRNA-seq 단일 모달리티
  • 결과 기대: 어떤 score를 넘으면 세포가 "tip"하는지
  • 코드: Python (R 환경 불필요), 본인 scanpy stack과 호환
왜 score를 axis로? 본인 데이터는 시간점이 없어요 (V1~V4, D1~D4는 replicate). DE-SWAN은 ≥3개 순서가 있는 점이 필요한데, 세포마다 SenePy score가 연속적으로 분포하니 이게 자연스러운 "유사 시간축"이 됨. 노화 진행도가 아니라 senescence 진행도를 본다고 생각하면 됨.

⚠️ Circularity — 가장 중요한 문제

SenePy score는 유전자 발현으로부터 계산됨. 그러니 "score와 함께 변하는 유전자"를 찾는 건 tautology가 될 위험. score를 정의하는 유전자가 score와 1:1 대응하는 건 당연한 거니까.

🛡️ 안전장치 3겹

  • ① 자동 제외: 정규 SenMayo gene list (Saul 2022) — 모듈 안에 박혀 있음
  • ② 사용자 제외: extra_genes_to_drop으로 본인 SenePy hub gene 추가 입력 가능
  • ③ Data-driven 제외: |Spearman(expr, score)| > 0.7인 유전자 자동 제거 (default threshold)
실전 팁: top_genes 컬럼을 봤을 때 익숙한 senescence marker가 꼭대기에 너무 많이 보이면 누출(leakage)을 의심하고 threshold를 0.5로 내리거나 extra_genes_to_drop에 본인 hub list를 추가하세요.

📜 senescence_deswan.py 핵심 함수 미리보기 (클릭해서 펼치기) 
def deswan_window(pb, bin_score, window_center, bucket_size, alpha=0.05):
    """At one window center, split bins at within-window median into
    low/high, run Welch t-test per gene, BH-correct, count q<alpha."""
    lo = window_center - bucket_size/2
    hi = window_center + bucket_size/2
    in_win = (bin_score >= lo) & (bin_score <= hi)
    sub = pb[in_win]
    sub_score = bin_score[in_win]
    median = np.median(sub_score)
    low  = sub[sub_score <  median]
    high = sub[sub_score >= median]
    t, p = stats.ttest_ind(high, low, axis=0, equal_var=False)
    _, q, _, _ = multipletests(p, method="fdr_bh")
    return int((q < alpha).sum())

🎯 결과를 어떻게 읽나 — 4가지 시나리오

🥇 시나리오 A: Veh에서 sharp crest, DQ에서 평탄해짐

가장 큰 win. DQ가 senescence commitment threshold를 무너뜨린다는 직접 증거. 그 crest의 top genes를 GSEA → 어떤 pathway가 "tip"되는지. G11BM 논문의 새 mechanistic axis가 됨.

🥈 시나리오 B: 두 condition 모두 crest, 위치는 다름

DQ가 threshold를 미루거나 (rightward shift) 당김 (leftward). Score 정량값으로 "DQ가 senescence를 평균 X점 만큼 늦춘다" 식 보고 가능.

🤷 시나리오 C: 여러 작은 crest, 하나의 큰 봉우리 없음

Senescence가 "단계적"으로 일어남. 단일 threshold가 아니라 sequence. 덜 임팩트 있지만 여전히 publish 가능 — staged senescence 모델.

📉 시나리오 D: 평평한 선, crest 없음

SenePy score는 연속 gradient고 내부 threshold가 없다는 뜻. Shen의 "44/60 봉우리"같은 게 senescence axis에선 없다는 negative result. 이것도 발견 — 적어도 monocytes에선 그렇다고 보고 가능.

🚀 다음 단계 (결과가 좋으면)

  • ① Pathway enrichment per crest: 본인 gsea_percelltype_aging.py의 GSEA 파이프라인에 crest 유전자 리스트를 직접 입력. peak_score를 ranking metric으로.
  • ② Cross-celltype comparison: 모든 cell type에서 crest 위치를 비교. "공통 threshold가 있는가, 아니면 cell-type-specific인가?"
  • ③ Veh vs DQ delta: 같은 cell type에서 Veh와 DQ crest의 위치/높이 차이. 이게 본인 senolytic 논문의 새 figure가 될 수 있음.
  • ④ Stretch — pseudotime axis: SenePy score 대신 HSPC → myeloid 분화 pseudotime을 axis로 써서 같은 분석. "분화 자체에 tipping point가 있는가?"
